## Phase 1: Unified 1-Line Bootstrapper (`install.sh`)

### Objective
Eliminate manual `.env` file editing and multi-step docker compose management. Provide a single `curl | bash` entrypoint that automatically sets up Master or Slave with zero friction.

### Master Node Installation Flow
```bash
curl -sSL https://raw.githubusercontent.com/<org>/dockermind/main/install.sh | bash -s -- --role master
```
- [x] **1.1 Environment & Dependency Pre-flight Check:**
  - Detect OS (`Ubuntu`, `Debian`, `RHEL`, `CentOS`, `macOS`).
  - Verify `docker` (>= 24.0) and `docker compose` plugin installed; offer auto-install if missing.
  - Verify ports `3000` (Dashboard), `8000` (Master API) are available.
- [x] **1.2 Admin Password & Cryptographic Secret Provisioning:**
  - **User-Defined Admin Password:** Prompt the user interactively:
    - `Enter Admin Password (min 8 chars) [or press Enter to auto-generate]:`
    - Masked input with password confirmation.
    - If left blank, defaults cleanly to username **admin** and password **admin** (matching the standard Grafana / dev-ops pattern).
  - **Cluster Internal Secrets (Auto-Generated):**
    - High-entropy `JWT_SECRET` (64-char hex via `openssl rand -hex 32`).
    - High-entropy cluster pre-shared `API_SECRET` for mutual slave-master authentication.
  - Write hardened configuration to `.env` with restrictive permissions (`chmod 600`).
- [x] **1.3 Certificate & Network Provisioning:**
  - Execute `scripts/gen_certs.sh` to generate cluster CA and server certificates for mTLS.
  - Create Docker network `dockermind` with pre-defined subnet.
- [x] **1.4 AI Provider Configuration Wizard:**
  - Interactive prompt (or CLI flags):
    - Option A: **Online (Google Gemini / OpenRouter)** &rarr; prompts for API key.
    - Option B: **Local (Ollama)** &rarr; auto-enables `--profile local` in docker-compose.
- [x] **1.5 Container Bootstrap & Cluster Join Token Generation:**
  - Execute `docker compose up -d`.
  - Print a styled **Cluster Launch Card** containing:
    - Dashboard URL: `http://<HOST_IP>:3000`
    - Generated Admin Credentials
    - **Exact 1-Line Copy-Paste Join Command** for Edge Slaves with pre-filled master IP and secret.

---

### Slave Node Installation Flow
```bash
# Automated Join (One-Liner generated by Master)
curl -sSL https://raw.githubusercontent.com/<org>/dockermind/main/install.sh | bash -s -- --role slave --master http://192.168.1.50:8000 --secret <CLUSTER_SECRET> --name node-edge-01
```
- [x] **1.6 Interactive & Non-Interactive Input Handler:**
  - If flags provided (`--master`, `--secret`), run completely headless.
  - If run interactively (`curl | bash -s -- --role slave`):
    - Prompt 1: `Master Node URL` (e.g., `http://192.168.1.50:8000`).
    - Prompt 2: `Cluster API Secret` (masked input).
    - Prompt 3: `Slave Node Identifier` (default: system hostname).
    - Prompt 4: `Container Runtime` (`docker` or `podman`).
- [x] **1.7 Agent Deployment:**
  - Verify connection to Master (`GET /health` with secret).
  - Launch `dockermind-slave` container or systemd unit with mounted socket.
  - Validate registration handshake (`200 OK`) and live status in Master topology.

## Phase 2: Prometheus & OpenTelemetry Metrics Exporter

### Objective
Enable SRE teams to scrape DockerMind metrics directly into existing monitoring stacks (Prometheus, Grafana, Datadog) without relying solely on the Web UI.

### Master Prometheus Endpoint (`GET /metrics`)
- [x] **2.1 Standard Prometheus Exporter Implementation (`master/routers/metrics.py`):**
  - Expose `GET /metrics` in standard Prometheus exposition format (`text/plain; version=0.0.4`).
- [x] **2.2 Metric Definitions & Gauges:**
  - **Cluster & Slave Health:**
    - `dockermind_slaves_total{status="online|offline"}`
    - `dockermind_node_cpu_usage_pct{node}`
    - `dockermind_node_memory_used_bytes{node}`
    - `dockermind_node_memory_total_bytes{node}`
    - `dockermind_node_disk_used_pct{node}`
  - **Container Infrastructure:**
    - `dockermind_containers_total{node, status="running|exited|paused"}`
    - `dockermind_container_memory_rss_bytes{node, container}` *(True RSS with inactive page-cache subtracted)*
    - `dockermind_container_cpu_usage_pct{node, container}`
    - `dockermind_container_restart_count{node, container}`
  - **SRE & AI Incident Telemetry:**
    - `dockermind_crashloop_active{node, container}` (Gauge: 1 = crashing, 0 = healthy)
    - `dockermind_ai_diagnoses_total{model, severity="critical|warn|ok"}`
    - `dockermind_healing_actions_total{action="restart|kill|recreate", status="success|failure"}`
    - `dockermind_alerts_active_total{severity}`
- [x] **2.3 Pre-built Grafana Dashboard Template:**
  - Create `monitoring/grafana/dockermind-dashboard.json`.
  - Include panels for Cluster Topology, True Memory Consumption Sparklines, Crash Loop Alerts, and AI Healing Action logs.

## Phase 3: Multi-Runtime Support (Podman, Docker Swarm, Kubernetes)

### Objective
Expand beyond standalone Docker to support Podman (rootless/enterprise Linux), Docker Swarm, and Kubernetes workloads.

### Phase 3A: Podman Runtime Support
- [ ] **3.1 Socket Auto-Detection in Go Slave Agent (`slave/collector.go`):**
  - Check for Podman system socket: `/run/podman/podman.sock`.
  - Check for Podman rootless user socket: `/run/user/<UID>/podman/podman.sock`.
  - Fall back to standard Docker socket: `/var/run/docker.sock`.
- [ ] **3.2 Podman Cgroup v2 & API Adaptations:**
  - Verify container inspect format compatibility with Podman REST API.
  - Test cgroups v2 memory controller paths under systemd slices (`system.slice` / `user.slice`).

### Phase 3B: Docker Swarm Integration
- [ ] **3.3 Swarm Service Discovery:**
  - Recognize Swarm service names and replica tasks (`service.1.xxx`).
  - Cluster overlay network topology rendering on UI.

### Phase 3C: Kubernetes Light Agent (Future Extension)
- [ ] **3.4 K8s DaemonSet Manifest & Pod Watcher:**
  - Light Go DaemonSet querying kubelet API or CRI socket.
  - Detection of `CrashLoopBackOff` and `OOMKilled` pod events.
  - Forward pod logs to DockerMind Master for AI Root-Cause Analysis.

## Phase 4: Enterprise RBAC & User Management Directory

### Objective
Provide full lifecycle user directory management directly in the Web UI for administrators, backed by persistent SQLite storage instead of ephemeral in-memory state.

### Backend Enhancements (`database.py` & `master/routers/auth.py`)
- [x] **4.1 Persistent SQLite User Store:**
  - Create table `users (username TEXT PRIMARY KEY, password_hash TEXT NOT NULL, role TEXT NOT NULL, created_at REAL, updated_at REAL)`.
  - Automatically migrate/seed initial Admin credentials on startup.
- [x] **4.2 Complete User Directory CRUD Endpoints:**
  - `GET /auth/users`: List all registered accounts with role and creation timestamp (Admin only).
  - `POST /auth/users`: Create new user with bcrypt-hashed password and assigned role (`viewer`, `operator`, `admin`).
  - `PUT /auth/users/{username}`: Update role permissions and/or reset password (Admin only).
  - `DELETE /auth/users/{username}`: Remove user account with safety checks (prevent self-deletion and root admin deletion).
  - Audit logging for every user creation, role update, and deletion in SQLite `audit_log`.

### Frontend Web UI (`dashboard/src/App.jsx`)
- [x] **4.3 Admin User Management Panel:**
  - Dedicated **"Users & RBAC"** section visible exclusively to `admin` role users.
  - User Directory Table: Username, Role Badge (`admin`, `operator`, `viewer`), Creation Date, and Action Buttons.
  - **Create User Dialog:** Form with username, secure password input, and role selection with privilege descriptions.
  - **Edit User Modal:** Change user role on-the-fly and reset credentials.
  - **Delete User Confirmation:** Modal preventing accidental lockout.

## Phase 5: Dynamic Integrations & Zero-Downtime Settings Vault

### Objective
Allow administrators to rotate AI API keys, configure Slack/Discord/Email notifications, and change LLM models directly from the Web UI with zero container redeployments and zero cluster downtime.

### Backend Engine (`master/config.py`, `master/llm_client.py`, `master/services/notifier.py`, `master/routers/settings.py`)
- [x] **5.1 Dynamic In-Memory Config Vault:**
  - In-memory cache loaded from SQLite `settings` table on startup with `.env` fallback.
  - Secret masking utility (`AIza...******...YXCg`) preventing visual credential leakage in UI and logs.
  - Live module-level dynamic attribute interception (`__getattr__`) ensuring zero-restart key rotation.
- [x] **5.2 Hot-Reloadable AI SRE Engine:**
  - `PUT /settings/ai`: Instant runtime switching between Google Gemini, OpenRouter, and Local Ollama.
  - `POST /settings/ai/test`: Real-time diagnostic latency and connectivity testing.
- [x] **5.3 Multi-Channel Alert Dispatcher & SMTP:**
  - Full SMTP / Email support with TLS/SSL encryption for Gmail App Passwords and corporate relays.
  - Slack Incoming Webhook and Discord channel integration.
  - Diagnostic ping dispatcher (`POST /settings/notifications/test`) with per-channel health status.

### Frontend Web UI (`dashboard/src/App.jsx`)
- [x] **5.4 Integrations & Vault Dashboard:**
  - Dedicated **"Integrations & Vault"** tab in sidebar navigation.
  - AI SRE Engine & Key Rotation card with provider switcher and test connection feedback.
  - Alert Webhooks & Email Notification card with Slack, Discord, and SMTP inputs.
  - Immediate toast notifications and zero-downtime hot-reload guarantees.
